## Read-only phase

`/speckit.analyze` is read-only. It does not create a commit, does not amend,
and does not change the branch. A repository that was born empty keeps the
specify/clarify commits on the feature branch; analyze does not add another
commit and does not create `main`.

## Copy the reference skeleton

Plan, tasks, and implement copy patterns from `.specify/reference/` (installed
by `specify init --stack nestjs-react`) and adapt them. Do not reinvent Prisma
config, auth, CASL, MCP, shadcn, or Playwright setup when that tree already
shows a working version.

## NestJS + React Analysis Requirements

After the core analysis, read `.specify/memory/stack-context.md` and `tasks.md`.

Mark **CRITICAL** when the project has no `AuthModule` and `tasks.md` lacks a blocking auth phase covering login, HttpOnly cookies, CSRF, rotating refresh with reuse detection, roles, and a user seed.

Mark **HIGH** when the feature includes authentication (login, account recovery, one-time passwords or tokens, session issuance, password change, or mail that carries auth secrets) and `spec.md`, `plan.md`, or `tasks.md` misses any authentication security rule or a test that covers it. A rule explicitly marked not applicable with a reason counts as covered. The rules are: single-use temporary passwords and tokens (atomic consume on first success, invalidated by a later successful login or password change); sin enumeración — account recovery and login do not reveal account existence or why a login was rejected (same status, body, and similar latency; every rejection path pays the Argon2 cost, verifying the stored Argon2id hash when one exists and otherwise a fixed dummy Argon2id hash — hash ficticio — with the same parameters as real hashes, including a missing account, a missing credential, an inactive user, a locked or blocked account, and any other 401 that does not verify a real hash; hashing, database writes, or email cannot change the response); contadores atómicos — lockout and rate-limit counters updated in one transaction (per-key lock or atomic upsert-increment), which explicitly forbid read-then-write and count-then-insert, reject inside that transaction, purge expired rows in the same transaction, and require a concurrency test; client IP from `request.ip` with `X-Forwarded-For` trusted only through an explicit validated trust-proxy setting; a must-change-password or otherwise restricted session with no business scopes, guards limited to change-password, logout, and me, and refresh that does not reissue scopes; TLS (`secure` or `requireTLS`) for outbound SMTP that carries secrets, with plaintext only for a loopback dev mail catcher; invalidation of access tokens and refresh tokens after password change or session revocation when issued before `passwordChangedAt` / `password_changed_at` or an older token version, with the refresh endpoint checking before it issues; guard bypasses (for example `/mcp`) compare the parsed path only and never use `originalUrl.includes` or `url.includes`. Do not mark this HIGH for a feature that does not include authentication.

Mark **CRITICAL** when a user story or functional requirement creates, updates, or deletes data, changes configuration, permissions, language, brand, or session, or is a security event (login, failure, lockout, recovery, impersonation), and `spec.md` has no **Eventos de bitácora** row for it. Pure reads are exempt unless the spec asks for an event. An exception counts only when that section states it and gives a reason. Mark **CRITICAL** when `tasks.md` has no implementation task and no test task for each event declared in **Eventos de bitácora**. A language change without an audit event is **CRITICAL**.

Mark **CRITICAL** when the feature has more than one locale, a language switcher, or translated product copy and `plan.md` or `tasks.md` omits **Locale resolution**: `apps/web/src/i18n/locale.ts` (preference, then the `locale` cookie, then the browser, then the organization default), `changeLanguage` only in a handler or a guarded effect, `labelKey` translated during render, or the `pnpm lint` rules `mas/no-i18n-mutation-in-render`, `mas/no-module-translation`, `mas/no-literal-copy`, and `scripts/check-i18n.mjs`. Mark **CRITICAL** when that feature adds login and `tasks.md` does not copy `.specify/reference/templates/i18n-login.spec.ts` (language change, text change, a later click within 500 ms, sign-in, reload keeps the locale, navigation changes without reload, no screenshots).

Mark **CRITICAL** when the project contains demonstration code or seed: a notes or widgets module, `model Note` or `model Widget`, `notes:*` or `widgets:*` permissions, `replace-example-slice`, or an `example.com` account. The skeleton has no example slice. Domain modules, screens, and accounts come from a Spec Kit feature. The skeleton seed inserts no rows.

Mark **CRITICAL** when a Prisma model has no `@@map` to an English snake_case plural table, when a camelCase field has no `@map` to snake_case, or when model names, mapped names, or persisted enum values use Spanish or Spanglish. A documented 1:1 external-source field may keep the source name on the model; its physical column must still be snake_case.

Mark **CRITICAL** when the feature uploads or accepts a file and `plan.md` or `tasks.md` omits **Subida de archivos**: `multipart/form-data`, `FileInterceptor` / `FilesInterceptor` / `FileFieldsInterceptor` / `AnyFilesInterceptor`, `limits.fileSize`, and a type check (`fileFilter` or `ParseFilePipe` with `FileTypeValidator` or a magic-byte validator). Mark **CRITICAL** when a file is planned as JSON base64 (`@IsBase64`, `fileContent`, `dataUrl`, a `data:` URI, or `Buffer.from(..., "base64")`) without an explicit cap of at most 1 MiB (`1_048_576`, `@MaxLength` or `z.string().max`) and a justified `mas/no-base64-file-upload` suppression. The lint rules are `mas/multipart-upload-limits`, `mas/no-base64-file-upload`, and `mas/base64-upload-max-length`.

Mark **CRITICAL** when the project breaks **Modularidad estricta** in the stack constitution: a domain outside `apps/api/src/modules/<dominio>/`, an `AppModule` that declares controllers or providers of a domain, a cross-module import that skips `index.ts`, Prisma outside `*.repository.ts` and the Prisma module, a `@Global()` module outside config, module-level `let` / `Map` / `Set`, a cycle, a feature page imported statically by the router, `fetch` in the shell, product code in `packages/ui`, a contract import that skips `@demo/contracts/<dominio>`, or a repository touching another domain's Prisma models. The enforcing rules are `mas/module-layout`, `mas/public-module-api`, `mas/prisma-only-in-repositories`, `mas/no-global-module`, `mas/no-module-state`, `mas/no-url-includes-in-guards`, `import-x/no-cycle`, `mas/lazy-feature-routes`, `mas/fetch-in-feature-data`, `boundaries/dependencies`, `mas/contracts-public-index`, `mas/own-models-only`, plus dependency-cruiser inside `pnpm lint`.

Mark **CRITICAL** when the project still uses `.eslintrc.cjs`, when `eslint-plugin-boundaries` does not keep `apps/api` and `apps/web` from importing each other (shared types and schemas belong in `packages/contracts`; `apps/api` must not import `@demo/ui`; `packages/contracts` must not import an app), when a controller or MCP tool touches Prisma, when product code calls `useEffect` outside `apps/web/src/shared/hooks/**` (server state goes through TanStack Query), when `process.env` or `requiredEnv` is read outside `apps/api/src/config` (Nest `ConfigModule` with Zod; also allowed: `prisma.config.ts`, `prisma/database-url.ts`, scripts, and e2e configs), when `@ts-ignore` or `@ts-expect-error` has no description, or when `eslint-disable` has no justification or ticket. Disabling `no-explicit-any` is **CRITICAL** even with a description.

Also mark **CRITICAL** when `tasks.md` has no tasks for `openapi:generate`, `api-client:generate`, or an AST-based CASL check in `pnpm verify`, or when it still requires `ensureQueryData`, `prisma/prisma.config.ts`, `MongoAbility` / `createMongoAbility` for Prisma queries, or gitignoring `routeTree.gen.ts`.

Mark **CRITICAL** when `tasks.md` has no CI job that, against a clean Postgres, runs `prisma generate`, `prisma migrate deploy` (failing if the output contains `No migration found`), seed, a real `node dist/main.js` process with HTTP 200 on `/api/v1/health`, API e2e, and Playwright.

Mark **CRITICAL** when `tasks.md` skips **Migraciones seguras sobre datos existentes**: no task for a new migration instead of editing one already applied in testing or production, no expand/contract plan for destructive changes, no `-- mas:allow-destructive <motivo>` requirement, no `pnpm lint` migration check (`scripts/lint-migrations.mjs` and the negative fixtures), or no `upgrade-on-data` job that migrates the base branch, seeds that database, and runs `prisma migrate deploy` for the pull request. The seed is not a deploy mechanism. A single local database is allowed only when `SEED_DATABASE_URL` is unset and `DATABASE_URL` uses `127.0.0.1`, `localhost`, or `::1`.

Mark **CRITICAL** when `tasks.md` is missing any of these test tasks:

- API e2e with supertest against real Postgres (not a mocked Prisma client): at least one test per REST endpoint, including 401, 403 from CASL, refresh-token rotation that rejects reuse, and throttling (429)
- MCP e2e with Bearer and scopes against that same Postgres: at least one test per MCP tool (401 without a token, denial for a missing scope, success with the required scope)
- Playwright plus axe-core: at least one spec per user story, with `screenshot`, `video`, and `trace` set to `'off'`
- When the spec ports an HTML prototype: **Prototype fidelity** tasks (tokens, brand assets, motion, shell design, `pnpm test:fidelity`). Mark **CRITICAL** when those tasks are missing, when a logo is planned as text, or when the shell design is left on skeleton defaults. Mark **CRITICAL** when the prototype repeats a pattern (settings cards, rows with a badge and a switch) and `plan.md` or `tasks.md` does not extract one component with that HTML structure (`panel-card`, `section-label`, `h5`, muted text, `hr.my-4`, label, badge, help, switch) plus a fidelity-map entry for computed `border`, `border-radius`, `box-shadow`, `padding`, typography (`font-family`, `font-size`, `font-weight`), and colors (`color`, `background`). Literal colors in that component are **CRITICAL**. Mark **CRITICAL** when the prototype defines an icon library and `plan.md` or `tasks.md` uses a different one (including `lucide-react` while the prototype uses Font Awesome, Material Symbols, or any other set). Mark **CRITICAL** when the tasks omit `apps/web/ui.icons.json`, the central module `apps/web/src/icons/index.ts`, per-icon npm imports, or `data-icon`. `lucide-react` is allowed only as the fallback when the prototype defines no icon library. Mark **CRITICAL** when literal colors are planned in components or in CSS outside `apps/web/src/index.css`, or when the fidelity tasks compare `:root` variables instead of computed color, hover, and active
- Unit tests for each domain service, each guard, and each CASL policy

A tasks file that only lists a few unit tests or a single Playwright spec fails this gate.

`/speckit.analyze` runs before implement and is read-only, so a missing `.nvmrc` is expected and is **not** by itself CRITICAL. Mark **CRITICAL** (not a warning) when `tasks.md` has no setup task that creates `.nvmrc` with the exact Active LTS version. When `.nvmrc` already exists, mark **CRITICAL** only when its major differs from that Active LTS. Also mark **CRITICAL** when the Node major in an existing `engines.node`, `@types/node`, CI, Docker, or the README differs from that Active LTS. Resolve the release at analysis time from `https://nodejs.org/dist/index.json` only: first entry whose `lts` is not `false` (newest-first file; highest Active LTS semver). Do not use memory, nodejs.org prose pages, Current, odd majors, or alpha/beta/rc. The setup task must write that exact version (strip `v`); the other pins must use its major. One-liner: `curl -s https://nodejs.org/dist/index.json | node -e 'let s="";process.stdin.on("data",c=>s+=c);process.stdin.on("end",()=>{const hit=JSON.parse(s).find(e=>e.lts!==false);if(!hit){console.error("no Active LTS");process.exit(1)}const exact=hit.version.replace(/^v/,"");console.log(exact);console.log(exact.split(".")[0])})'`. As of 2026-11-13 the example is `26.13.1` / major `26` (Lithium); Node 22 is Maintenance. The rule is the index, not a hardcoded `26`.
